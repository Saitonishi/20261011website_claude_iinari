# 吉田村風土記 ホームページ 作り方ガイド（初心者向け）

## 0. 何ができあがるのか

- ページの一番上に地図が出ます。
- 地図の点（ポイント）をクリックすると、その場所の解説と写真が**下に**出ます。
- 解説は6つの章に分かれています。**解説も写真もない章は、自動で隠れます。**
- 写真は**章ごとに何枚でも**付けられます。
- ポイントの追加は QGIS で、解説と写真の追加は専用の**入力フォーム**で行います。

### 3つの道具の役割

| 道具 | 役割 | 置き場所 |
|---|---|---|
| QGIS | ポイントの**位置**を決める（写真のGPSは使わない） | 自分のパソコン |
| GitHub Pages | 地図ページを公開する | インターネット |
| Google（スプレッドシート・ドライブ・Apps Script） | 解説と写真を保存し、入力フォームを動かす | Google アカウント内 |

```
QGIS で位置を作る → points.geojson → GitHub に置く ─┐
                                                    ├→ 公開ページ（地図＋解説）
入力フォーム → Google スプレッドシート＋ドライブ ─────┘
```

## 2. 手順

### 手順A　まず動きを見てみる（5分・任意）

1. このフォルダ内で、ターミナル（コマンドプロンプト）を開きます。
2. 次を入力して Enter。
   ```
   python -m http.server 8000
   ```
3. ブラウザで `http://localhost:8000` を開きます。サンプルの3点が表示されます。
4. 終わったら、ターミナルで `Ctrl + C`。

※ `index.html` をダブルクリックで開くと、データが読み込めず動きません。必ず上の方法か、手順Cの公開後に見てください。

### 手順B　QGIS でポイントの位置を作る

1. QGIS で「ポイント」のレイヤーを作ります（新規 GeoPackage / シェープファイルなど）。
2. 属性（フィールド）は次の2つだけ作ります。

   | 名前 | 型 | 入れる内容 |
   |---|---|---|
   | `id` | テキスト | `Y001` のような**重複しない番号**。一度付けたら**変えない** |
   | `name` | テキスト | 地点の名前（例：村はずれの道標） |

3. 地図や古い資料を見ながら、位置を打って確定します（ここが「清書」です）。
4. レイヤーを右クリック →「エクスポート」→「地物を別名で保存」
   - フォーマット：**GeoJSON**
   - 座標参照系（CRS）：**EPSG:4326 - WGS 84**
   - 保存するフィールド：`id` と `name` だけにチェック
   - ファイル名：`points.geojson`
5. このフォルダの `points.geojson` を、書き出したもので**上書き**します。

> **id は解説との「つなぎ目」です。** あとで id を変えると、登録した解説・写真とのつながりが切れます。

### 手順C　GitHub Pages で公開する

1. GitHub にログインし、右上の「＋」→「New repository」。
2. Repository name に `yoshida-fudoki`（好きな名前で可）と入力、**Public** を選び「Create repository」。
3. 作ったリポジトリの画面で「uploading an existing file」を押し、
   このフォルダの中身（`gas` フォルダ以外のすべて：`index.html`、`style.css`、`app.js`、`config.js`、`points.geojson`、`sample-content.json`、`images` フォルダ）をドラッグ＆ドロップ →「Commit changes」。
4. 「Settings」→「Pages」→ Branch を `main`、フォルダを `/ (root)` にして「Save」。
5. 1〜2分待つと `https://（あなたのユーザー名）.github.io/yoshida-fudoki/` で見られます。

> `gas` フォルダは GitHub に置く必要はありません（Googleの画面に貼り付けます）。

### 手順D　Google 側を用意する（解説・写真の保存先とフォーム）

1. **スプレッドシートを作る**：Google ドライブで新しいスプレッドシートを作り、名前を「吉田村風土記データ」などにします。
2. **Apps Script を開く**：メニュー「拡張機能」→「Apps Script」。
3. **Code.gs を貼る**：最初からある `コード.gs` の中身をすべて消し、このフォルダの `gas/Code.gs` の中身を貼り付けます。
4. **Form を追加する**：左の「ファイル」横の「＋」→「HTML」→ 名前を `Form`（`.html` は付けない）にし、`gas/Form.html` の中身を貼り付けます。
5. **設定を書き換える**（Code.gs の上のほう）：
   - `EDIT_PASSWORD`：**自分だけの合言葉**に変更（`CHANGE_ME` のままだと動きません）
   - `GEOJSON_URL`：手順Cで公開した `points.geojson` のURL
     （例 `https://ユーザー名.github.io/yoshida-fudoki/points.geojson`）
6. **setup を1回実行する**：画面上部の関数選択で `setup` を選び「実行」。
   「承認が必要です」と出たら、自分のGoogleアカウントを選び、
   「詳細」→「（プロジェクト名）に移動」→「許可」。
   （自分で作ったスクリプトなので、この警告は正常です。）
   実行後、スプレッドシートに `points` と `photos` のシートができ、ドライブに「吉田村風土記_写真」フォルダができます。
7. **ウェブアプリとして公開する**：右上「デプロイ」→「新しいデプロイ」→ 種類の歯車で「ウェブアプリ」。
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   →「デプロイ」。表示される「ウェブアプリのURL」（`…/exec` で終わる）をコピー。

### 手順E　地図ページとつなぐ

1. `config.js` を開き、`GAS_URL: ""` の引用符の中に、手順Dでコピーした URL を貼ります。
2. 修正した `config.js` を GitHub に上げ直します（リポジトリで `config.js` を開き、鉛筆アイコンで編集 → Commit でも可）。
3. 公開ページを開き直すと、「サンプルを表示しています」の黄色い帯が消えます。

### 手順F　入力フォームを開く

- ウェブアプリのURLの末尾に `?page=form` を付けて開きます。
  例：`https://script.google.com/macros/s/…/exec?page=form`
- このURLはブックマークしておくと便利です。

## 3. 日々の使い方

### 新しいポイントを追加するとき

1. QGIS でポイントを追加（`id` と `name` を入れる）。
2. `points.geojson` を書き出し直し、GitHub に上書きします。リポジトリの画面で「Add file → Upload files」を選び、**同じ名前**（`points.geojson`）のファイルをアップロードして「Commit changes」を押すと上書きされます。
3. 1〜2分後、フォームのポイント一覧にも自動で出ます。

### 解説と写真を登録するとき

1. 入力フォームを開き、**合言葉**を入れ、**ポイントを選んで**「このポイントを開く」。
2. 6つの章のうち、書ける章だけ解説を入力します（**空欄の章は公開ページに出ません**）。
3. 写真は章ごとの「ファイルを選択」から**複数枚まとめて**選べます。1枚ずつキャプション（撮影年・撮影者・出典など）を入れられます。
4. 「保存する」を押します。写真の数だけ時間がかかります。
5. 公開ページを再読み込みすると反映されます。

### 後から直すとき

- **解説の修正**：フォームで同じポイントを開くと、登録済みの文章が入っています。直して保存すれば上書きされます。
- **写真を消す／表示順を変える**：スプレッドシートの `photos` シートで、その写真の行を削除します（公開ページから消えます）。並び順は `order` の数字で変えられます。ドライブ内のファイルは残るので、不要なら手で削除してください。
- **写真の追加**：フォームから追加するだけです（既存の写真は残ります）。

## 4. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 黄色い帯に「サンプルを表示しています」 | `config.js` の `GAS_URL` が空です。手順E。 |
| 「解説データを読み込めませんでした」 | `GAS_URL` の間違い、または手順Dの⑦で「アクセスできるユーザー」が「全員」になっていません。 |
| フォームで「合言葉が違います」 | `Code.gs` の `EDIT_PASSWORD` と一致していません（コピペ時の空白に注意）。 |
| フォームのポイント一覧が出ない | `Code.gs` の `GEOJSON_URL` が間違っているか、GitHub に `points.geojson` が上がっていません。 |
| 「先に setup を実行してください」 | 手順Dの⑥を実行してください。 |
| `Code.gs` を直したのに反映されない | 「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →「バージョン：新バージョン」→「デプロイ」。**URLは変わりません。** 「新しいデプロイ」にするとURLが変わるので注意。 |
| iPhone の写真が選べない／読み込めない | 形式が HEIC の場合があります。iPhone の設定「カメラ」→「フォーマット」→「互換性優先」にするか、JPEG に変換してください。 |
| 点が押しにくい | 地図の上の「ポイント一覧」のボタンからも選べます。 |

## 5. 公開前に確認してほしいこと

- **位置情報の公開範囲**：地図に出る位置は誰でも見られます。個人宅、お墓、祠、希少な動植物の場所など、公開してよいか事前に確認してください。気になる場所は QGIS で少しずらす／ポイントにしない、という選択もあります。
- **写真の権利と肖像権**：古い写真は、撮影者・所蔵者の許諾や、写っている方の了承を確認してください。キャプションに出典を書いておくと後で助かります。
- **写真のGPS情報**：フォームは写真を縮小して送るため、元の位置情報（EXIF）は**自動的に消えます**。
- **合言葉の扱い**：合言葉を知っている人は誰でも書き込めます。共有する人を限り、時々変えてください（変えたら `Code.gs` を更新して再デプロイ）。
- **データのバックアップ**：スプレッドシートとドライブのフォルダが「本体」です。ときどき「ファイル → コピーを作成」で控えを取ってください。

## 6. 補足：章の見出しを変えたいとき

見出しは2か所に同じ内容で書いてあります。変えるときは**両方**直してください。

- `app.js` の `CHAPTERS`
- `gas/Form.html` の `CHAPTERS`

（章の数を増やす場合は、さらに `gas/Code.gs` の `CHAPTER_KEYS` と、スプレッドシート `points` シートの列も増やす必要があります。必要になったら相談してください。）

## 7. 補足：QGIS の範囲や路線も重ねたいとき

範囲（ポリゴン）や路線（ライン）のレイヤーは GeoJSON で書き出して、`layers/` フォルダなどに置き、`config.js` の `EXTRA_LAYERS` に書くと地図に重なります。

```js
EXTRA_LAYERS: [
  { name: "旧村境", url: "layers/boundary.geojson", color: "#1d4e89" },
],
```
